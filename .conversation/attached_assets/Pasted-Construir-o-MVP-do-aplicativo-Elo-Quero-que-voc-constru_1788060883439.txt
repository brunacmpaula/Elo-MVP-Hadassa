Construir o MVP do aplicativo "Elo"
Quero que você construa um MVP funcional de um aplicativo mobile chamado Elo.
1. Conceito
O Elo conecta missionários e apoiadores, permitindo que missionários compartilhem atualizações, pedidos de oração e necessidades com pessoas que desejam acompanhar e participar de sua missão.
O conceito central é:
"Mesmo longe, juntos na missão."
O principal diferencial técnico do aplicativo é ser offline-first, especialmente para a experiência do missionário.
O missionário pode estar em uma região com internet limitada ou completamente sem conexão e ainda deve conseguir usar as principais funcionalidades do aplicativo. Os dados devem ser armazenados localmente e sincronizados automaticamente quando a conexão retornar.

2. Escopo do MVP
Não implemente funcionalidades além das descritas abaixo.
O MVP possui dois tipos principais de experiência:
Missionário
Pode:
	•	visualizar seu perfil;
	•	publicar atualizações;
	•	criar pedidos de oração;
	•	criar necessidades;
	•	visualizar seus conteúdos;
	•	editar conteúdos;
	•	usar o aplicativo offline;
	•	visualizar o status de sincronização.
Apoiador
Pode:
	•	criar perfil;
	•	descobrir missionários;
	•	visualizar perfil de missionários;
	•	seguir/deixar de seguir missionários;
	•	visualizar atualizações;
	•	visualizar pedidos de oração;
	•	visualizar necessidades;
	•	marcar "Estou orando";
	•	visualizar quais missionários acompanha.
Não implemente neste MVP:
	•	pagamentos reais;
	•	PIX;
	•	chat;
	•	mensagens privadas;
	•	sistema de organizações;
	•	dashboard administrativo;
	•	mapa;
	•	gamificação;
	•	vídeos;
	•	IA;
	•	sistema complexo de notificações;
	•	microservices;
	•	funcionalidades de rede social além das descritas.

5. Comportamento offline
Este é um requisito fundamental.
Quando o missionário estiver offline:
Criar atualização
Deve ser possível criar uma atualização normalmente.
O aplicativo deve:
	1	salvar a atualização no SQLite;
	2	adicionar uma operação na fila de sincronização;
	3	mostrar que a atualização está pendente;
	4	não exibir erro simplesmente porque não existe internet.
Exemplo de estado:
📴 Salvo no dispositivo Será sincronizado quando a conexão estiver disponível.
Quando a conexão voltar:
Offline
   ↓
Internet disponível
   ↓
Sync Engine
   ↓
Enviar operações pendentes
   ↓
Servidor confirma
   ↓
Marcar como sincronizado
A sincronização deve possuir:
	•	retry;
	•	idempotência;
	•	tratamento de falhas;
	•	estados pending, syncing, synced e failed.
Se uma operação falhar, ela não deve ser perdida.

6. O que deve funcionar offline
Para o missionário:
Deve funcionar offline:
	•	abrir seu perfil;
	•	visualizar seus conteúdos já sincronizados;
	•	criar atualização;
	•	criar pedido de oração;
	•	criar necessidade;
	•	editar conteúdos já existentes;
	•	visualizar fila de sincronização.
Pode depender de internet:
	•	descobrir novos missionários;
	•	seguir novos missionários;
	•	receber conteúdo novo;
	•	sincronizar;
	•	login inicial.
O aplicativo deve deixar claro quando está offline, mas sem tornar a experiência frustrante.

7. Usuários
Existem dois tipos de experiência:
MISSIONARY
SUPPORTER
No login, o usuário possui uma experiência correspondente.
Porém, estruture o modelo de usuário de forma que futuramente uma mesma pessoa possa exercer os dois papéis. 
Importante: o missionário não poderá se cadastrar, ele será cadastrado por uma igreja na plataforma para aumentar a credibilidade
Não crie dois aplicativos diferentes.
É um único aplicativo React Native com experiências diferentes.

14. Design
O aplicativo deve ser:
	•	simples;
	•	bonito;
	•	moderno;
	•	acolhedor;
	•	humano;
	•	minimalista.
Não quero aparência de sistema administrativo.
Quero uma experiência que transmita:
	•	proximidade;
	•	esperança;
	•	comunidade;
	•	simplicidade.
Use bastante espaço em branco.
Use as cores branco, verde, bege e alguns detalhes em vinho
Cards simples.
Tipografia legível.
Hierarquia visual clara.
Evite excesso de elementos e de textos

15. Acessibilidade básica
Mesmo não sendo o foco principal do MVP, implemente boas práticas:
	•	labels acessíveis;
	•	suporte a leitor de tela;
	•	contraste adequado;
	•	áreas de toque grandes;
	•	tamanho de fonte respeitado;
	•	não depender somente de cores para indicar estados;
	•	suporte a Dynamic Type quando possível.

17. Design da sincronização
Implemente a sincronização de maneira confiável.
Exemplo:
User creates post
        ↓
SQLite transaction
        ↓
Post saved locally
        ↓
Sync operation created
        ↓
UI shows PENDING_SYNC
        ↓
Connectivity restored
        ↓
Sync engine runs
        ↓
POST /sync
        ↓
Backend processes operation
        ↓
Backend returns ACK
        ↓
Local record becomes PUBLISHED
        ↓
Sync operation becomes SYNCED
Nunca remova uma operação da fila antes de receber confirmação do servidor.

19. Qualidade do código
Quero código:
	•	tipado;
	•	modular;
	•	legível;
	•	testável;
	•	com responsabilidades bem separadas.
Evite:
	•	componentes gigantes;
	•	lógica de negócio dentro das telas;
	•	chamadas HTTP diretamente nos componentes;
	•	acesso direto ao banco dentro da UI;
	•	duplicação;
	•	abstrações desnecessárias.

23. Prioridade
Se precisar escolher entre funcionalidades, siga esta ordem:
Prioridade 1
Offline-first e sincronização confiável.
Prioridade 2
Fluxo Missionário → publicação → sincronização → Apoiador.
Prioridade 3
Pedidos de oração.
Prioridade 4
Seguir missionários.
Prioridade 5
Design e refinamentos visuais.
Não sacrifique o funcionamento offline para adicionar funcionalidades.

24. Resultado esperado
Entregue um projeto funcional que permita demonstrar esta história:
Uma missionária está em uma região sem internet. Ela cria um pedido de oração no Elo. O aplicativo salva o conteúdo localmente. Quando a conexão retorna, o aplicativo sincroniza automaticamente. Um apoiador recebe a atualização, decide acompanhar a missionária e marca que está orando por ela.
O MVP deve ser pequeno, mas funcional de ponta a ponta.
Não quero apenas mockups ou telas estáticas. Quero que o fluxo principal funcione de verdade.
Comece pela estrutura do projeto e pela arquitetura. Depois implemente o backend, banco de dados, mobile e sincronização offline. Ao final, forneça instruções claras para executar o projeto localmente.
